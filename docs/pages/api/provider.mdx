# Provider

`@openlv/provider` exposes an EIP-1193 style provider with OpenLV session lifecycle management.

Most dApps should use `@openlv/connector` instead of calling this directly.

## Exports

- `createProvider(parameters)`
- `ProviderStatus`

## Basic usage

```ts
import { createProvider } from '@openlv/provider'

const provider = createProvider({
  config: {
    signaling: {
      p: 'mqtt',
      s: {
        mqtt: 'wss://test.mosquitto.org:8081/mqtt',
      },
    },
    transport: {
      p: 'webrtc',
    },
  },
})

await provider.request({ method: 'eth_requestAccounts' })
const chainId = await provider.request({ method: 'eth_chainId' })
```

## Parameters

- `config?`: protocol defaults (signaling + transport)
- `storage?`: settings and saved-session backend (defaults to localStorage where available)
- `openModal?`: optional UI hook used by connector/modal integrations

## Provider helpers

- `createSession(parameters?)`
- `restoreSession()`: returns the current session if one exists; otherwise restores a saved pairing, rejecting if none is saved
- `closeSession()`
- `getAccounts()`
- `status`
- `error`
- `session`

## Provider states

`ProviderStatus` values:

- `standby`
- `creating`
- `connecting`
- `connected`
- `error`

## Events

Provider emits state/session events including:

- `connect`
- `accountsChanged`

## Saved sessions

Settings and saved sessions use the same `storage` adapter, with separate keys. In browsers this defaults to localStorage; outside browsers, the fallback is in-memory storage. Session parameters include serialized private keys and replay counters, so scripts on the same origin can read them.

Enable `autoReconnect` through `provider.storage.setSettings` to save connected sessions and counter updates. When a provider is constructed with this setting and a saved pairing, it starts restoration automatically. `restoreSession()` can also restore explicitly saved parameters.

An authentication failure or a resumption timeout removes the saved pairing and exposes the reason through `provider.error`. Recovery requires a fresh pairing, not another `restoreSession()` call. Closing the session also deletes its saved parameters.
