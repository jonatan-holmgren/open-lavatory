# Session

In openlv, a session is the part that maintains the lifecycle of the connection.
A session is created from either side as the QR code is scanned or URL is copied.
And signaling and transport layers handle everything behind the scenes.

## Creating a session

You can create a session for example in a dApp as follows:

```typescript
import { createSession } from "@openlv/session";

const session = await createSession({
  sessionId: "mytestsession111",
  p: "ntfy",
  s: "https://ntfy.sh/",
});

await session.connect();
```

## Connecting to a session

You can connect to a session using the url as follows:

```typescript
import { connectSession } from "@openlv/session";

const session = await connectSession("openlv://...");

await session.connect();
```

## Identifying yourself to the peer

Both sides can pass an optional `info` object; it is carried in the [`capabilities` handshake packet](/api/handshake#capabilities) and shown in the other peer's UI:

```typescript
const session = await connectSession(
  "openlv://...",
  onMessage,
  [webrtc()],
  {
    info: {
      identity: "com.example.wallet",
      name: "Example Wallet",
      icon: "data:image/png;base64,...",
    },
  },
);
```

The remote peer's info is part of the session state, set the moment the capabilities exchange completes:

```typescript
session.peerInfo.subscribe((peerInfo) => {
  console.log(peerInfo?.name, peerInfo?.identity);
});

// or read it directly
const peerInfo = session.peerInfo.get();
```

## Transport negotiation

The transport array passed to `createSession`/`connectSession` doubles as your preference list.
During the handshake both peers exchange their supported transports and the first entry in the dApp's list that the wallet also supports is used — see [transport selection](/api/handshake#transport-selection).

## Resuming a pairing

After the session connects, `getConnectionParameters()` returns the local keypair, pinned peer key, negotiated transport identifier, pairing identity, and replay counters. The provider persists these parameters through its `storage` adapter, which defaults to localStorage in browsers.

Pass saved parameters to `createSession` to authenticate the same pairing and rebuild its connection using the saved transport. Both peers must still support that transport; resumption does not exchange capabilities again.

Provide `onConnectionParametersChange` in the session options to synchronously persist counter updates before resumption frames are published. A storage write failure aborts resumption; do not catch the error and continue sending.

An authentication failure or a 45-second resumption timeout disconnects the session and sets `session.error`. Delete the saved pairing and re-pair through a fresh `openlv://` URI. A failed session cannot be reconnected.

Receiving `close` tears down signaling and transport and rejects pending requests.
